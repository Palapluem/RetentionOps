## Local AI choice

The project does not require a hosted AI account, API key, or provider credits. Ollama runs
`qwen3:4b-instruct` on the developer's Mac and binds to `127.0.0.1:11434`. `OLLAMA_NO_CLOUD=1`
was set when starting Ollama. The initial model download was about 2.5 GB and remains in the
Ollama model directory outside the repository, Docker build context, images, and volumes.
Inference then runs locally; device memory, compute and electricity are the local operating
costs. The model path is optional and does not affect normal API/dashboard reads.

The direct local API call returned `status=ready`, model `qwen3:4b-instruct`, and
`advisory_only=true`. Its two approved observations described a 100-row mature synthetic test
cohort with 14 labeled churns (14.0%) and verified event completeness through the
2026-11-03 evaluation freeze. The returned next step asks the analyst to review cohort
denominators. No customer identifiers were returned.

The browser sends no prompt/body. The API constructs an allowlisted aggregate payload, accepts
only enumerated observation/next-step IDs, and renders the displayed facts itself. The route
requires exact same-origin and a documented loopback Host (`localhost` or `127.0.0.1` on
ports 3000/3100); the API also requires the fixed internal action header. One local inference
is allowed at a time with a 10-second process cooldown. Cross-origin and rebinding-style Host
requests are rejected in browser tests. Ollama was not added to Compose.

## Limits

All data and labels in this evidence are generated synthetic fixtures. These results do not
establish KKBox results, licensed source access, production identity/authentication, GCP or
Vercel deployment, live performance, campaign uplift, or customer outcomes. Cloud resources
and real-source use remain gated by project account, budget, source-rights, label-definition,
IAM, and owner-review decisions.
